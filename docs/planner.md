# 聚合复用规划器：证明接口与安全约定

`reuse_data/planner/` 在资料读取层之上实现一个**带覆盖证明**的细粒度聚合复用规划器。
核心原则：只有语义上足够的信息才能替代基表扫描；任何无法在登记结构内证明的
包含/互斥/可导出关系，一律显式判 `unknown` 或 `rejected`，绝不比较 SQL 字符串、
绝不猜测不支持的逻辑。

## 模块划分

| 模块 | 职责 |
| --- | --- |
| `ast_nodes.py` | 受限 AST 登记、序列化/反序列化、结构校验。未登记节点直接拒绝 |
| `logic.py` | SQL 三值逻辑求值（True/False/UNKNOWN）与 DNF 规范化、NOT 下推 |
| `ranges.py` | 半开区间 `[lower, upper)` 表示与包含/相交判定 |
| `predicate.py` | 谓词包含证明、互斥证明、过滤列保留检查、3VL 安全补集 |
| `aggregates.py` | 可合并聚合状态、合并/最终化语义、AVG 与 COUNT DISTINCT 可导出性 |
| `catalog.py` | 缓存资产登记、来源快照/分区版本、内容摘要、等价证明、失效管理 |
| `coverage.py` | 单缓存资格证明、分区级版本剪枝、互斥块并集覆盖、成本模型 |
| `planner.py` | 分区组合搜索、预算控制、成本选择、计划与排除原因输出 |
| `executor.py` | 执行期复验（失效/摘要/来源/分区版本）、缓存块+补偿扫描合并 |
| `reference.py` | 独立逐事实参照引擎，结果袋核对，不走任何复用路径 |
| `fixtures.py` / `scenarios.py` | 受控小资料夹具与端到端场景 |

## 三个核心证明接口

### 1. 谓词包含 `prove_implies(cached, query)`

证明命题（三值逻辑下）：对任意行 `r`，`cached(r) IS TRUE ⇒ query(r) IS TRUE`。

- 双方先规范化为 DNF；缓存 DNF 的**每个**合取分支都必须蕴涵查询的某个分支，
  任一存在反例的分支判 `rejected`，无法分析的结构判 `unknown`。
- 合取分支按列建模：等值常量、`IS NULL`/`IS NOT NULL`、有序区间、`<>`。
- NULL 严格按 3VL：`NULL = 1` 为 UNKNOWN 而非 TRUE，因此 `tenant IS NULL`
  不能推出 `tenant = 'A'`。
- 区间包含比较的是查询在该列上的**合并区间**是否落在缓存区间内；有界缓存
  不能回答无界查询（缓存外的行可能满足查询）。
- `prove_disjoint(p1, p2)` 证明两块行集合不可能同时为 TRUE，用于重叠检测；
  恒真谓词与任何谓词都不互斥。

### 2. 聚合可导出性 `prove_aggregates(query, cache_groups, cache_states)`

- 分组：缓存分组键必须是查询分组键的超集（可更细，向上汇总），否则拒绝。
- **AVG** 只能由 `sum_<col>` 与 `nonnull_<col>` 重建；对已平均结果再平均会
  得到错误的月均（日均值的平均 ≠ 总和/非空计数），缺任一组件即拒绝。
- 全 NULL 组：`SUM/AVG/MIN/MAX -> NULL`，`COUNT(col)=0`，`COUNT(*)` 仍计行。
- 空输入：分组查询返回零行；全局聚合仍输出一行，`COUNT=0`，其余 `NULL`。
- **COUNT DISTINCT** 仅当缓存保留完整可合并身份集合
  （`distinct_ids_<col>`）时允许复用；普通 `COUNT(*)`/`COUNT(col)` 不可替代。

### 3. 覆盖切分与版本绑定

- 事实表按半开日分区登记，查询区间必须与分区边界对齐，不对齐直接报错而非猜测。
- 缓存资格 = 静态绑定（失效/来源表/schema/摘要/状态版本）+ 逐分区版本绑定
  + 谓词包含 + 过滤列保留 + 分组/聚合可导出，全部通过才成块。
- 过滤列规则：查询过滤用到的列，若不在缓存分组键中、也不是缓存谓词里可证明
  的等值常量，则该缓存不能再按此列筛选，显式排除。
- 分区版本不同且无登记的等价证明时，该分区从缓存可用集合剪枝，转基表补偿；
  查询不会半旧半新。等价证明（如不改数据的压缩）登记后才允许混用。
- 同分区多块必须通过互斥证明；`prove_union_covers` 再证明块并集恰好覆盖
  查询真集，覆盖完整则不发基表扫描，否则生成 3VL 安全补偿谓词
  `P_query AND (P_c IS NOT TRUE)...`，NULL 行不会被错误丢弃。

## 成本搜索与预算

- 成本只采用**登记扫描量**：基表按事实分区行数，缓存按物化块读取成本；
  缓存“创建时间更新”本身不构成适用理由。
- 逐分区枚举互斥缓存组合，组合收益按实际登记成本计算（不做简单相加假设），
  选成本最低且全部通过证明的方案。
- 预算（搜索节点数）耗尽时，枚举未完成的分区放弃复用、回退基表；任何时候
  纯基表扫描都是安全兜底。

## 执行期复验

执行器在读取每个缓存块前重新验证：失效标记、来源表、schema 指纹、内容摘要
（SHA256）、聚合状态版本，以及块内每个分区的版本绑定。计划生成后被失效或
摘要被篡改的缓存直接抛 `ExecutionError`，绝不返回旧结果。

## 复用成功的判定

端到端场景同时满足才算成功：

1. 复用计划结果与独立逐事实参照引擎的**结果袋逐组相等**；
2. 基表事实读取量确实低于纯基表方案（`fact_rows_read < total_fact_rows`）。

覆盖场景：不同组大小的平均、NULL 过滤、重叠日期缓存、部分分区修订（含等价
证明分支）、查询空集（分组与全局两种语义）、过滤列丢失、宽谓词残差过滤、
COUNT DISTINCT 身份集合、预算耗尽、计划后失效、摘要损坏、纯基表兜底。

## 运行

```sh
python -m unittest discover -s tests -v          # 全部单测（含原资料检查）
python -m compileall -q reuse_data tests
python -m reuse_data.cli data/normal.json        # 原资料完整性检查
python -m reuse_data.cli plan                    # 规划场景 + 参照引擎核对
```
